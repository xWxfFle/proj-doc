# Как внести вклад в руководство по стилю

--8<-- "includes/menu-root.md"

## Как предложить изменение

1. Создайте ветку от `main`:

   ```bash
   git checkout main
   git pull
   git checkout -b docs/short-description
   ```

2. Внесите правки в `docs/` и при необходимости обновите `mkdocs.yml`.
3. Проверьте локально (см. ниже).
4. Сделайте коммит в формате Conventional Commits.
5. Откройте Pull Request в `main` и опишите *зачем* меняете правило.
6. Дождитесь ревью минимум одного участника.

Небольшие опечатки можно исправлять сразу в PR без отдельного issue.

## Требования к коммитам (Conventional Commits)

Формат:

```text
<type>(optional-scope): <краткое описание на русском или английском>
```

Типы:

| type | Когда |
| --- | --- |
| `docs` | Правки содержимого руководства |
| `feat` | Новый раздел / новая возможность сайта |
| `fix` | Исправление ошибки в правилах или сборке |
| `ci` | Изменения GitHub Actions |
| `chore` | Зависимости, служебные файлы |

Примеры:

```text
docs(language): уточнить правило обращения на «вы»
feat(accessibility): добавить раздел доступности текста
ci: включить строгую сборку MkDocs
```

## Процесс ревью

Ревьюер проверяет:

- соответствие предложения цели стайлгайда;
- наличие примеров «хорошо / плохо», если меняется правило;
- обновление навигации `mkdocs.yml`, если добавлен файл;
- прохождение CI (lint + build).

Автор отвечает на комментарии или вносит правки новым коммитом.
После approve выполняется merge в `main` (squash или merge commit — по договорённости команды).

## Локальная сборка

```bash
# Python-зависимости
python -m venv .venv
# Windows:
.\.venv\Scripts\activate
pip install -r requirements.txt

# Node-зависимости (линт)
npm install

# Линт
npm run lint

# Предпросмотр
mkdocs serve
```

Сайт будет доступен на <http://127.0.0.1:8000>.

Строгая сборка (как в CI):

```bash
mkdocs build --strict
```

## Как добавить новый раздел

1. Создайте файл в `docs/rules/` или другой подходящей папке, например `docs/rules/accessibility.md`.
2. Напишите H1 и правила с примерами.
3. Добавьте пункт в `nav` файла `mkdocs.yml`.
4. Запустите `npm run lint` и `mkdocs build --strict`.
5. Откройте PR с типом `feat` или `docs`.
