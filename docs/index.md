# Стайлгайд технической документации

--8<-- "includes/menu-root.md"

Руководство по стилю для **документации веб/SaaS-продукта**: пользовательские руководства, API-документация, README, release notes и внутренние гайды команды разработки.

## Зачем это нужно

Единые правила помогают:

- писать документы быстрее и предсказуемее;
- снижать стоимость ревью;
- сохранять единый голос продукта;
- подключать новых авторов без долгого онбординга.

## Быстрый старт

1. Прочитайте раздел [назначение и область применения](about/purpose.md).
2. Следуйте [правилам языка и тона](rules/language.md) и [структуре документов](rules/structure.md).
3. Проверьте оформление по [правилам форматирования](rules/formatting.md).
4. Перед PR запустите локальный линт и сборку — порядок описан на странице [как предложить изменение в руководство](contributing.md).

## Принципы

| Принцип | Суть |
| --- | --- |
| Ясность | Читатель понимает действие с первого прочтения |
| Краткость | Нет воды и повторов |
| Единообразие | Одинаковые вещи описаны одинаково |
| Проверяемость | Примеры и шаги можно воспроизвести |
| Доступность | Текст читается людьми и вспомогательными технологиями |
