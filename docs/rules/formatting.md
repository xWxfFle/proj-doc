## Markdown

- Заголовки оформляйте как `#` … `####`. Глубже не уходите.
- В файле оставляйте один H1.
- Между заголовком и текстом ставьте пустую строку.
- Для маркированных списков используйте `-`, для нумерованных шагов — `1.`.
- Код в строке выделяйте backticks: `` `project_id` ``.
- Блоки кода оформляйте fenced-блоком с указанием языка:

````markdown
```bash
mkdocs serve
```
````

## Выделение

- **Жирный** используйте для UI-элементов и важных ограничений: нажмите **Сохранить**.
- *Курсив* используйте для введения термина при первом упоминании.
- Не используйте CAPS LOCK для акцента.

Пример фразы: «Откройте *организацию* и нажмите **Пригласить участника**.»

## Таблицы

Используйте таблицы для сравнения вариантов, параметров API и пар «избегать / предпочитать».

Не используйте таблицы для длинных абзацев.

Пример таблицы параметров API:

| Параметр | Тип | Обязательный | Описание |
| --- | --- | --- | --- |
| `name` | строка | да | Название проекта |
| `private` | булево | нет | Скрыть проект из общего списка |
| `owner_id` | строка | да | Идентификатор владельца проекта |

Пример таблицы ролей:

| Роль | Можно создавать проекты | Можно управлять ключами |
| --- | --- | --- |
| Наблюдатель | нет | нет |
| Редактор | да | нет |
| Администратор | да | да |

## Admonitions (MkDocs)

Для предупреждений используйте блоки admonition:

```markdown
!!! warning "Важно"
    Без API-ключа запрос вернёт `401`.
```

Типы: `note`, `tip`, `warning`, `danger`.

Пример `tip`:

```markdown
!!! tip "Подсказка"
    Для локальной проверки сохраните ключ в переменную `PROJECT_API_KEY`.
```
