# Структура документов

## Выбор типа документа

Типы документов называйте по-русски (в скобках — привычный английский термин из Diátaxis):

| Тип документа | Вопрос читателя | Структура |
| --- | --- | --- |
| Обучение (tutorial) | «Как начать с нуля?» | Цель → предусловия → шаги → проверка результата |
| Инструкция (how-to) | «Как сделать X?» | Цель → шаги → результат / ошибки |
| Справка (reference) | «Что означает параметр?» | Алфавит / группы полей, без сюжета |
| Пояснение (explanation) | «Почему так устроено?» | Контекст → концепция → связь с другими частями |

## Обязательные блоки в начале

Каждый документ (кроме коротких справочных страниц) начинается с:

1. **Заголовка H1** — что описывает страница
2. **Краткого введения** (1–3 предложения) — для кого и зачем
3. **Предусловий** (если нужны права, версии, доступы)

## Именование файлов

- Только латиница, нижний регистр, дефисы: `create-api-key.md`
- Имя файла отражает тему, не номер: не `doc1.md`
- Один файл — одна тема

## Длина страницы

- Целевая длина: до экрана 3–5 минут чтения
- Если больше — разбейте на подразделы или отдельные страницы и свяжите перекрёстными ссылками

## Навигация MkDocs

Новый раздел добавляйте в меню навигации `mkdocs.yml` → `nav` в том же PR, что и контент.
Без пункта в `nav` страница не появится в боковом меню сайта.
