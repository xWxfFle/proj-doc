# Как пользоваться стайлгайдом

## Для автора

1. Перед написанием нового документа определите тип по-русски: обучение, инструкция, справка или пояснение.
2. Выберите шаблон структуры в разделе [структура документов](../rules/structure.md).
3. Пишите по правилам языка и терминологии.
4. Перед отправкой на ревью прогоните линт Markdown и локальную сборку MkDocs.
5. Порядок внесения правок в сам стайлгайд описан на странице [как предложить изменение в руководство](../contributing.md).

## Для ревьюера

Проверяйте документ чек-листом:

- [ ] Есть цель документа и целевая аудитория
- [ ] Заголовки отражают действия или сущности, а не «Общее»
- [ ] Термины совпадают со словарём
- [ ] Шаги нумерованы, результат шага понятен
- [ ] Примеры кода компилируются / запускаются или помечены как псевдокод
- [ ] Нет канцелярита и двусмысленностей

## Приоритет правил

Если правила конфликтуют:

1. Ясность для читателя
2. Согласованность с уже опубликованными документами продукта
3. Общее правило из этого стайлгайда
