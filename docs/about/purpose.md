## Объект стайлгайда

Стайлгайд описывает правила написания и оформления **технической документации программного продукта** (веб-приложение / SaaS):

- пользовательская документация: инструкции, обучение, устранение неполадок;
- документация для разработчиков: API, SDK, интеграции;
- служебные файлы репозитория: README, CONTRIBUTING, CHANGELOG;
- release notes и анонсы изменений.

Примеры страниц в области стайлгайда: «Как пригласить участника», «Параметры `POST /webhooks`», «Что нового в версии 2.4».

## На кого распространяется

- технические писатели;
- разработчики, которые пишут README и комментарии к API;
- аналитики и продакт-менеджеры, которые готовят описания функций;
- ревьюеры документации в Pull Request.

## Что вне области

- маркетинговые лендинги и рекламные тексты;
- юридические документы (оферта, политика ПДн) — для них отдельные шаблоны;
- дизайн UI/UX — это зона product design system.

## Источники вдохновения

Правила опираются на практику Docs as Code, подходы Google Developer Documentation Style Guide и опыт open-source проектов с MkDocs и Sphinx.
